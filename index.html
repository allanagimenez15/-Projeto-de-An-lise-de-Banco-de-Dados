O Problema

O Desafio da
Cafeteria

Sistemas tradicionais de estoque rastreiam produtos que entram como A e saem como A. Uma caixa de leite entra, uma caixa de leite sai.

Em uma cafeteria, a lógica é diferente: múltiplos insumos se transformam em uma única receita. O leite, o xarope, o café e o gelo entram separados — e saem juntos como um Iced Caramel Macchiato.

Este projeto modela exatamente essa transformação, tornando possível calcular o custo exato de cada bebida, controlar o estoque de ingredientes e analisar a margem de lucro — tudo de forma automática.

Arquitetura

Modelo de
Dados

01

insumos

Matérias-primas: nome, unidade, quantidade na embalagem, preço e custo unitário calculado automaticamente.

CREATE TABLE insumos (
  id   INT AUTO_INCREMENT
       PRIMARY KEY,
  nome VARCHAR(100) NOT NULL,
  unidade ENUM('ml','g','un'),
  qtd_embalagem DECIMAL,
  preco_compra  DECIMAL,
  custo_unitario DECIMAL
    GENERATED ALWAYS AS
    (preco_compra /
     qtd_embalagem) STORED
);
02

produtos_finais

Itens do cardápio: nome, tamanho e preço de venda final ao cliente.

CREATE TABLE produtos_finais (
  id   INT AUTO_INCREMENT
       PRIMARY KEY,
  nome VARCHAR(100) NOT NULL,
  tamanho  VARCHAR(20),
  preco_venda DECIMAL(10,2)
);
03

receitas

Ficha técnica: liga cada insumo ao produto final com a quantidade exata utilizada.

CREATE TABLE receitas (
  id         INT AUTO_INCREMENT
             PRIMARY KEY,
  produto_id INT,
  insumo_id  INT,
  quantidade_usada DECIMAL,
  FOREIGN KEY (produto_id)
    REFERENCES produtos_finais(id),
  FOREIGN KEY (insumo_id)
    REFERENCES insumos(id)
);
consulta_lucratividade.sql
SELECT p.nome AS Produto, p.tamanho, SUM(r.quantidade_usada * i.custo_unitario) AS custo_producao_total, p.preco_venda, (p.preco_venda - SUM(r.quantidade_usada * i.custo_unitario)) AS lucro_bruto FROM produtos_finais p JOIN receitas r ON p.id = r.produto_id JOIN insumos i ON r.insumo_id = i.id GROUP BY p.id; -- Resultado: Iced Caramel Macchiato | Grande | R$7.73 | R$22.00 | R$14.27
